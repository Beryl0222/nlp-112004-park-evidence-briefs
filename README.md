# 生态论证简报中的缺席陈述和补查决定

青砾自然保护区的踏查卡来自几个固定调查季。以下地名、物种和团队为演练所用，代号不与真实位置相连。手记有原始版与会审补交版。区划名录的 parent 有值时表示从属，includes 表示登记的一组覆盖成员。

## 本地资料

全部为 UTF-8 编码的合成业务资料。`data/contract.json` 中的列类型带 `?` 时可以是 JSON null。每组记录的 `id` 在该组中唯一，跨组关系以字段说明和清单的 `links` 为准。文字字段保留来源原句，嵌套对象按表中现有格式记录。

- `data/plots.json`。区划、旧称及调查单元。codes 表示历史中可出现在手记的称呼。
- `data/methods.json`。会审使用的调查方法与可判缺席的适用条件。
- `data/surveys.json`。队长登记的出队元数据。日、方法、路线槽位只描述计划和到场时间，完成情况看手记。
- `data/notes.json`。踏查手记、转引和勘误。引用可能同时在 note 原文与 refs 中记载。loggedAt 是接件时间。
- `data/bookings.json`。当季补查资源和已经确认的派工。每个状态对应队伍的实际占用，状态约定见下文。
- `data/hearing.json`。发布简报实际摘录与专家意见。references 记录当时被引用的手记。

## 使用约定

会审以物种、调查单元、季节为证据适用单位。正观察也要能归到具体适用范围。只有方法卡允许且满足完整观察数量才可以宣布调查条件下未记录，不能宣布该物种不存在。其他材料可以作为待核或局部观察描述。近重复的转引不增加独立调查数量。静听的时段由场次所处当地日出的前后一小时确定，4 月日出按 06:00，5 月按 05:50。
青鸣鸟的这一轮调查在 5 月 31 日结束，苇鳞鱼在 5 月或 10 月都可用，任务同组时按登记的对象数占资源。已派出任务不得自动拆散或改期。资源为同一队的实际窗口，不可拿晚过适用期的窗口代替本期覆盖。会审中可由专家决定取消某次仍有缺口的预约，此时相关缺口仍须保留。

## 读取与检查

使用 Node.js 22.23.4，依赖仅用 Node.js 标准库。资料检查依次读入各组 JSON，检查列类型、组内编号及已登记的组间引用，并列出各组记录数。读取入口为 `tools/materials.mjs`，可单独读取一组记录，或读取整个已登记资料包。

```sh
npm run check-data
npm test
```

## 证据强度与简报应用

在资料读取之上，`src/` 实现了一套不改动原始资料的证据管线，`tools/` 与 `web/` 是它的两个界面。

- `src/domain.mjs`。物种、季节、日出窗口、方法适用月份与会审约定的集中配置。
- `src/places.mjs`。区划名册与历史称呼解析。登记 codes 重叠（如“西埂”“老坡”）时返回多个候选单元，交专家待核，不把整区画成阴性；“这里/那一头”等指示词只在上下文唯一时落定。
- `src/statements.mjs`。把手记拆成 **观察、未观察、推测、征引、纠正** 五类陈述，每条保留原句、独立调查编号、季节、地点解析、方法是否实际采用与有效性问题（雨噪、网具待核、时段越窗等）。勘误（`previous`）生成纠正陈述并取代原卡同地点陈述；解析不掉的原句进入 `parseWarnings`，不静默丢弃。
- `src/ledger.mjs`。按 物种 × 调查单元 × 季节 汇总。重述与转引不增加独立调查数量；只有满足方法卡 `completedMin` 的完整有效未观察才可判“条件下未记录”，绝不等于物种不存在；同时列出覆盖缺口与地点待核项。
- `src/hearing.mjs`。按方法适用边界决定每条说法是“可面向公众 / 仅可作待核假设 / 暂不发布”；片区级说法要求每个从属单元都有合格证据；已发布说法发生实质变动时生成带手记引用的更正说明。局部可引用结果不会随有争议的整区结论一起被删。
- `src/planner.mjs`。补查名额安排：已派出任务不得自动拆散或改期，同队窗口按对象数占容量合并出队，晚过适用期的窗口不能代替本期覆盖；过季冲突交给专家选择优先处置，并显示搁置后哪些说法暂时无法升级。专家可整单取消预约，缺口仍保留。
- `src/app.mjs`。编排上述模块，并提供 `explainClaim` 结论溯源（成立依据、限定条件、被谁勘误或推翻）。

### 命令行与 Web

```sh
npm run report                     # 打印台账、可发布简报、待核假设、补查清单、更正说明
npm run report -- --explain "claim|青鸣鸟|G|2026 春季"   # 单条结论的逐条溯源
npm run serve                      # http://localhost:8080 工作台
```

Web 工作台的“补查清单”页可登记专家的优先处置、整单取消与地点核定；这些操作通过 `/api/decisions` 返回一份新规划，不会回写 `data/` 中的原始资料。

### 关键判定口径

1. “没听见叫声”是一条陈述，“在合适时段做完调查仍未记录到”是台账层面的合格缺席；雨噪、未完成场次、网具待核都不计有效。
2. 征引与重述回到同一独立调查；征引中的“这里”与本卡地点范围不一致时标记 `citedScopeMismatch`，覆盖不自动迁移。
3. 先前缺席与后来新发现按各自季节与范围同时保留；跨季说法（如“上一秋季曾有……”）按说法自己的季节评审。
4. 计划挂名但手记未提及的单元、其他方法顺带的“看一眼”，都不产生该对象的阴性缺口。
5. 历史调查季的缺口单独列示，不拿当季窗口顶替，也不占用当季专家处置名额。
